# 06 — Дистиляція: із сирих чатів у знання

Найвідповідальніший етап. Дистилят (`knowledge/*.md`, memory-ноти) годує семантичний
пошук → пошук годує модель → модель говорить із людиною. **Криве самарі = впевнена
напівправда, яку система подаватиме як факт роками.** Тому правила нижче — залізні.

## Артефакти

- `_KNOWLEDGE.md` (+ тека `knowledge/*.md`) — тематичні самарі з провенансом.
- `_TOPICS.md` — тематичний покажчик: кожен чат приписаний до кластера (жоден не сирота).
- Ланцюг навігації: `MEMORY.md → _INDEX → _KNOWLEDGE/_TOPICS → сирий чат`.

## Правила анти-галюцинації

1. **Дата на кожному твердженні.** Винесений факт несе `[ДД.ММ.РРРР]` джерела.
   Факт без дати не виносити. Тренд — як дельта: «станом на ДАТА — X; на пізнішу
   ДАТА — вже Y», не плоске «X».
2. **Версійність інструментів.** Інструмент із версіями (моделі, софт) — вказувати
   ЯКУ версію і СТАНОМ НА КОЛИ. Назва без версії+дати = майбутня брехня пошуку.
3. **Сутності ≠ інструменти.** Кодові назви проєктів людини не зливати з назвами
   моделей/продуктів в один заголовок. Тримай глосарій сутностей (окрема ref-нота).
4. **Провенанс обов'язковий.** Кожен інсайт лінкує на чат-джерело wikilink-ом
   (`[[YYYY-MM-DD_Назва_id]]`). Вільний факт без джерела не виносити.
5. **Флаг замість впевненості.** Не можеш датувати/верифікувати → пиши
   `⚠️ неверифіковано`, не перетворюй на впевнену прозу.
6. **Сире ≠ факт.** Сирий чат — розмова, де модель часто помилялась. Виносити лише
   те, що витримує перехресну перевірку (кілька чатів / підтвердження людини),
   з маркером джерела.
7. **Чутливе — окремо.** Приватні/сенситивні розмови: у зовнішній обіг (спільні
   бази, продукти, демонстрації) іде ЛИШЕ курована самарі, не сирі чати. Спитай
   людину, які кластери сенситивні, ДО дистиляції.

## Процес (ітеративно, не «за раз»)

1. Побудуй кластери: пройди `_INDEX.md`, згрупуй чати по темах → чернетка `_TOPICS.md`.
   🙋 Покажи людині — вона знає своє життя краще, ніж назви чатів.
2. По одному кластеру: прочитай сирі чати → напиши самарі за правилами вище →
   `knowledge/<кластер>.md`.
3. Після кожного кластера: `librarian.py index --source knowledge` + тестовий search —
   самарі має спливати вище сирих чатів.
4. Ключові факти про людину/проєкти → окремі memory-ноти (вони живуть далі, самарі —
   якір-довідка).
5. Рядок у `log.md` (операція `ingest`).

## Жива база: насичення після дистиляції

Дистиляція — не разова подія. Нове відкриття в роботі → дельта з датою у відповідну
самарі/ноту. Звичка «дописати дельту», а не «створити ще один файл поруч».
