# 10 — Переносимість: Codex та інші агенти

## Спільні інструменти поза harness

`task.py`, `archive_sessions.py`, `brain_refresh.py` і `distill_delta.py` — звичайні CLI,
тому однаково працюють з Claude Code, Codex та іншими агентами. Відрізняється лише спосіб,
яким агент отримує правила: Claude Code читає `CLAUDE.md`/skills, Codex — `AGENTS.md`/skills.
Автозапуск не є частиною portability: його вмикає людина окремим явним рішенням.
> Додано 10.07.2026 за результатами зовнішнього аудиту (GPT-5.6 Sol). Головна теза аудиту,
> яку тут закриваємо: **дані системи переносні, а поведінковий harness — ні.**

## Принцип

Кит стоїть на двох ногах:

1. **Дані** — Markdown, SQLite, Obsidian, Git, Python-скрипти. Модель-незалежні.
   Будь-який агент, що вміє читати файли й запускати shell, працює з ними одразу.
2. **Дисципліна** — хуки Claude Code (semantic_recall, memory_lint, pre_compact,
   session_start). Це ПОДІЇ харнеса: модель не «просять» шукати пам'ять — її змушують.
   Ця нога прибита до Claude Code.

Наслідок: у іншому агенті база працює, але дисципліна тримається на слухняності моделі,
а не на механіці. Це деградація, і її треба усвідомлювати чесно.

## Що працює з коробки в БУДЬ-ЯКОМУ агенті

- сирі архіви й memory-ноти (Markdown);
- `librarian.py` — звичайний CLI: `python scripts/librarian.py search "тема"`;
- усі адаптери читають той самий `search --format json` контракт; regex по людському
  текстовому виводу не є підтриманим API;
- `sanitize.py`, конвертери, `setup.sh`;
- Obsidian vault і graph view;
- Git-історія;
- PLAYBOOK як інструкція будь-якій здібній моделі.

## Адаптер для Codex CLI

Мапінг шарів дисципліни (Claude Code → Codex):

| Claude Code | Codex | Ступінь еквівалентності |
|---|---|---|
| `~/.claude/CLAUDE.md` | `AGENTS.md` (глобальний або в репо) | повна — переклади правила з templates/CLAUDE.md.template |
| `.claude/skills/` | `.agents/skills/` | висока — скіли є файлами, копіюються |
| `session_start` (хук) | стартова секція AGENTS.md: «першою дією прочитай bridge.md» | часткова — інструкція, не подія |
| `semantic_recall` (хук) | AGENTS.md + локальний `librarian search --format json` перед твердженням про минуле | слабша за hook, але retrieval і контракт ті самі |
| `memory_lint` (хук) | правило: «після запису ноти запусти scripts/hooks/memory_lint.py вручну» | часткова — скрипт той самий, тригер ручний |
| `pre_compact` (хук) | правило: «наприкінці сесії — доіндексація + сейв bridge.md» | часткова |

Мінімальний старт: скопіюй `templates/CLAUDE.md.template` → `AGENTS.md`, додай угорі блок
«стартовий ритуал» (bridge.md → librarian search по задачі) і «фінальний ритуал»
(запис у memory → `index --source memory` → оновити bridge.md).

До AGENTS.md також додай: експертна задача → доменний hub/skill до вердикту;
temporal intent («останнє», «після дати») → `--after/--before`; перед «не знайшов» →
2–3 переформулювання + keyword/source-фолбек.

## Що НЕ переноситься і чому це важливо

Головна перевага Claude Code-версії — примусовість: пошук пам'яті стається до відповіді
незалежно від того, «захотіла» модель чи ні. В агентах без хуків єдині шляхи повернути
примусовість:

- **wrapper-скрипт** — обгортка, що сама викликає librarian і вклеює результат у промт;
- **дисципліна правилами** — найслабше, але безплатно.

Обирай за ставками: для експериментів досить правил, для бойової роботи — wrapper.
ChatGPT/Cowork підтримується лише там, де середовище має локальний terminal/filesystem
доступ. MCP і публічний тунель до приватного vault не входять у Kit.

## Відомі межі системи (з того ж аудиту, підтверджено)

- **Експорти хмарних чатів — не жива синхронізація.** ChatGPT/Gemini/Claude-веб треба
  реекспортувати вручну (раз на місяць-два). Локальні сесії агентів МОЖНА індексувати
  щодня скриптом за розкладом — але тільки за явною згодою людини (див. docs/07).
- **Пласка структура має стелю.** Сотні нот — ок; десятки тисяч зажадають дедуплікації,
  entity resolution і правил superseded-фактів. Не будуй цього наперед — став, коли заболить.
- **Дистиляція лишається ризиковою** навіть із правилами docs/06 — людський аудит
  вибіркових фактів не скасовується.
