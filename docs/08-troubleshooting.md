# 08 — Troubleshooting

## Ollama / embed

- **`search` падає «Ollama недоступний»** → 🙋 запустити застосунок Ollama (або
  `ollama serve`). Перевірка: `curl -s localhost:11434/api/tags`.
- **Нема моделі bge-m3** → `ollama pull bge-m3` (≈1.1 ГБ разово). Модель має бути
  ТА САМА для індексації і пошуку — інші embedding-моделі несумісні по векторах
  (доведеться повний реіндекс).
- **Повільно на слабкому Mac** → нормально: пошук ~0.5–6 с; перший індекс великого
  архіву — хвилини-години. Індексуй по одному source, не all.
- **Хочеться хмарний фолбек** → `openrouter_enabled=true` у config.toml + ключ у
  env `OPENROUTER_API_KEY` або env_file. Та сама модель `baai/bge-m3` → без реіндексу.

## Конвертери

- **`conversations.json not found`** → перевір, що `--src` вказує на РОЗПАКОВАНУ
  теку експорту (не на zip і не на батьківську теку).
- **Gemini: 0 сесій** → перевір шлях `My Activity/Gemini Apps/MyActivity.html`
  усередині Takeout; мова акаунта Google може міняти назви тек — знайди html через
  `find Takeout -name "MyActivity.html"`.
- **Битий/обрізаний json** → перекачати експорт; конвертери не лікують биті файли
  (сире = першоджерело, його не можна «доправляти»).
- **Повторний прогін щось «пропустив»** → це норма: hash збігся, файл не змінювався.

## Індекс

- **`database is locked`** → у WAL-режимі рідкість; перевір, чи не висить старий
  процес індексації (`ps aux | grep librarian`). Дочекайся або вбий.
- **Індекс роздувся / сміття від видалених файлів** → найпростіше: видалити
  `index.db*` і переіндексувати all (локально = $0, лише час).
- **Search знаходить не те** → перевір `stats`: чи проіндексоване потрібне джерело;
  спробуй 2-3 формулювання запиту синонімами; звузь `--source`.

## Хуки

- **Хук не спрацьовує** → шляхи в settings.json мають бути АБСОЛЮТНІ (без ~);
  перевір `python3 <шлях>/semantic_recall.py </dev/null` — має мовчки вийти.
  Після зміни settings.json потрібна нова сесія.
- **«validation failed» від PreCompact** → у stdout PreCompact-хука щось потрапило;
  він має бути німим (див. коментар у pre_compact.sh).
- **semantic_recall шумить нерелевантним** → підніми поріг: MAX_DIST 1.05 → 0.95
  у semantic_recall.py.

## Obsidian

- **Не бачить symlink-тек** → Obsidian підтримує symlinks; перевір що vault відкрито
  САМЕ в `vault.root`, а не в одній з підтек. Graph view: увімкни «Existing files only».
- **Wikilink на чат не резолвиться** → лінк має бути на basename файлу без .md
  (`[[2026-06-01_Назва_abc123]]`), файл — усередині vault (через symlink архіву).

## Загальний принцип

Сирі шари (експорти, конвертовані чати) — незнищенні першоджерела: будь-який
зламаний похідний шар (індекс, самарі, symlinks) відновлюється з них заново.
Паніка недоречна; видаляти сире — злочин.
